"proposal-module-server": minor
---

Sign-in and proposal settings move from frontend build variables to server settings that the server enforces. New server settings: `WALLETSIGNER_USER_TYPES` (default `stake,drep`), `WALLETSIGNER_USER_DEFAULT` (default `drep`), `WALLETSIGNER_MULTISIG` (default `false`), `PROPOSAL_SIGNER_TYPES` (default `stake`) and `MAINTENANCE_MESSAGE` (unset shows no banner). An invalid value stops startup with a message naming it. Sign-in refuses a type that is not allowed, and refuses the multisig path when it is off. Creating, updating, deleting and withdrawing one's own proposals refuses a sign-in type outside `PROPOSAL_SIGNER_TYPES`. Those actions also always refuse a multisig session, because a multisig sign-in proves only that the signing key is named in the script, not that its threshold is met. `GET /health` returns the settings and the frontend reads them there at runtime. The frontend build variables `VITE_WALLETSIGNER_USER_TYPES`, `VITE_WALLETSIGNER_USER_DEFAULT`, `VITE_WALLETSIGNER_MULTISIG` and `VITE_MAINTENANCE_MODE` are no longer read and can be removed from the build; the build no longer requires `VITE_WALLETSIGNER_USER_TYPES`. Operators who relied on those variables must set the server settings, and the default sign-in type is now `drep`.
